# Архитектура Launcher Next

## Границы системы

`Anthology.Launcher` отвечает за пользовательский интерфейс и запуск игры. Он не содержит приватных ключей и не решает, какие файлы публиковать.

`Anthology.Community.Api` отделяет изменяемый контент от desktop-релиза: новости, видео, каталог модов, каналы, опросы и баг-репорты можно развивать без пересборки лаунчера. Текущая in-memory реализация — локальный прототип границы API; production-этап добавит PostgreSQL, объектное хранилище, аутентификацию, модерацию и админ-панель.

`Anthology.Update.Core` — независимое ядро доставки. Оно валидирует подписанный manifest, выбирает зеркало, докачивает артефакт, сверяет размер/SHA-256 и применяет подготовленные файлы транзакционно. UI получает прогресс, но не обходит проверки.

`Anthology.Releaser` работает только на стороне разработчиков: собирает детерминированный архив, считает хеш и подписывает manifest. Благодаря единому формату два разработчика могут публиковать совместимые пакеты, не синхронизируя вручную монолитный EXE.

## Поток обновления

```text
Releaser → подписанный manifest + ZIP → несколько хранилищ
                                      ↓
Launcher → проверка подписи → выбор зеркала → .partial/SHA-256
                                      ↓
                         staging → backup/journal → install
                                      ↘ ошибка: rollback
```

## Принятые решения

- `.NET 10 LTS`: единый стек для Windows UI, API и инструментов разработчика.
- WPF + Blazor Hybrid: нативное окно и системная интеграция, а основная UI-разметка остаётся быстро изменяемой веб-компонентной частью.
- Версионированные контракты `/api/v1` и `schemaVersion`: сервер и клиент можно выпускать независимо.
- ECDSA P-256 + SHA-256: manifest подтверждает автора и целостность; каждый артефакт проверяется отдельно.
- Зеркала описываются данными, а провайдеры — адаптерами. Добавление S3/CDN/собственного файлового сервера не меняет формат пакета.

## Доверительные границы

- UI и remote content считаются недоверенными.
- Видео встраивается только с разрешённых HTTPS-хостов.
- Пути manifest не могут быть абсолютными, содержать диски или `..`.
- Обновление не считается готовым до проверки размера и SHA-256.
- Приватный ключ отсутствует в лаунчере и репозитории.
- Переход на новую версию не меняет старый update channel автоматически.
