# Update Protocol v1

Manifest — JSON-объект с `payload` и `signature`. Подписывается каноническая JSON-сериализация `payload` алгоритмом `ecdsa-p256-sha256` в формате IEEE P1363.

## Package

- `id`, `displayName`, `version`, `kind` — идентификация пакета;
- `installRoot` — логический разрешённый корень (`launcher`, `game`, `modpack`, `database`, `engine`, `mods`, `tools`);
- `archiveFormat` — в v1 только `zip`;
- `size`, `sha256` — обязательная проверка артефакта;
- `mirrors` — источники в порядке `priority`;
- `files` — полный список безопасных относительных путей в архиве.

## Провайдеры зеркал

- `github`, `google-drive`, `direct` и произвольное имя direct-провайдера используют готовую прямую HTTPS-ссылку;
- `yandex-disk` принимает публичную ссылку и получает временный URL через API Яндекс Диска;
- `local-file` принимает `file:///...` URI и предназначен только для локальной разработки и общей сетевой папки команды;
- новые хранилища реализуют `IMirrorResolver`, не затрагивая проверку пакета.

Обычная страница Google Drive не гарантирует прямую загрузку больших файлов. Для production следует использовать опубликованную прямую ссылку, Google Cloud Storage/S3-совместимое хранилище или отдельный resolver с официальным API.

## Алгоритм клиента

1. Получить manifest только по HTTPS.
2. Проверить `schemaVersion`, структуру, allowlist корней и путей.
3. Найти доверенный публичный ключ по `keyId`, затем проверить подпись.
4. По очереди пробовать зеркала; сохранять поток в `.partial` и использовать HTTP Range при поддержке сервера.
5. Проверить точный размер и SHA-256, затем атомарно переименовать файл.
6. Распаковать в staging с повторной проверкой путей и списка файлов.
7. Применить через transaction journal; при любой ошибке восстановить backup.

Проверка подписи, выбор зеркала, безопасная распаковка, транзакционная установка и журнал установленных версий объединены в рабочий оркестратор. Self-update самого лаунчера остаётся отдельным следующим этапом, потому что запущенный EXE нельзя безопасно заменять без bootstrapper.

## Совместная публикация

Релиз создаётся из зафиксированного input-каталога. Manifest и artifact должны лежать вне input. Оба разработчика используют один CLI и один формат версий, а публикация разрешается только после CI. Production-подпись выполняет назначенный release owner или CI с защищённым secret; приватный ключ не пересылается между рабочими ПК.
